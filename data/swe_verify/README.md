# SWE-bench Verified Trajectory Labeling (Method-Validation Pilot)

Labeled trajectories for SWE-bench Verified, generated by the advisor's labeling
plan. This is the method-validation pilot: 10 instances x 3 trajectories = 30
rollouts, fully labeled and merged into prefix trees.

## Pipeline

1. `gen_ds_rollout_v2.py` - DeepSeek native function-calling rollout
   (tools: bash / read / edit). Env: N_SAMPLES, MAX_TURNS, TEMP; args [start] [end].
2. `label_rollouts.py` - render numbered transcript -> DeepSeek labels every
   assistant message as 0/1:
   - 0 = (a) read-not-used, (b) redundant repeat, (c) failed attempt later
     replaced, (d) overwritten by later action
   - 1 = otherwise (useful action)
3. `build_verified_trees.py` - merge trajectories into a prefix tree keyed by
   action signature (md5 of tool name + args); edge label = 0/1 label.
4. `summary_label.py` - aggregate report.

## Files

| Path | Description |
| --- | --- |
| validate10.json | The 10 selected validation instances (SWE-bench Verified subset) |
| rollouts/ | 30 raw trajectories, named `<instance_id>__s<k>.json` |
| labels/ | Per-trajectory message labels 0/1, same naming |
| task_trees.jsonl | Prefix trees (edges = actions, labeled 0/1), one line per instance |

## Pilot Results (2026-09-20)

- 716 labeled edges: label=1 -> 349 (49%), label=0 -> 367 (51%)
- Rollout outcomes: pass 1 / fail 18 / unknown 11
- Key finding: rollouts ran in bare cloned repos missing dependencies, so
  pass rate is low (1/30). Production labeling should execute tools inside the
  official SWE-bench eval images.

## Usage (example)
